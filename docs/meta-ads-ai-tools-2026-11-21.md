# Meta Ads AI tools for a purchase-conversion support app

**Research date: 2026-11-21 · Vietnam-based solo advertiser · US hair-product e-commerce**

## Tóm tắt

- Dùng **Meta Ads Manager**, **Automated Rules** và **Events Manager** để theo dõi trước khi trả thêm phí cho tool. Cảnh báo CPA/ROAS không cho biết ngay Pixel/CAPI bị lỗi: hãy đối chiếu số đơn trong cửa hàng, độ trễ attribution và tình trạng nhận Purchase events.
- Với creative, hãy thử nhiều **hook**, **primary text**, **headline** và **CTA** bằng English cho thị trường US; dùng ảnh sản phẩm thật, kiểm tra bản preview trên Feed, Reels và Stories, rồi đánh giá theo Purchase/CPA/ROAS thay vì chỉ theo CTR hay AI score.
- Có thể chọn **A — Alerts only**, **B — Alerts + Optimisation**, **C — Alerts + Optimisation + Creative AI**, hoặc **D — Full Meta Ads copilot**. Có thể ghép tính năng giữa các gói, ví dụ chọn A và chỉ thêm Creative Studio từ C. B–D giữ quyền duyệt thay đổi budget hoặc publish ở phía chủ tài khoản.

## Evidence and Meta access

Only official public vendor/Meta pages were used as evidence. No accounts or trials were opened, no application submitted, no Meta account connected, no personal information entered, and nothing purchased. Public documentation establishes advertised capabilities, not this owner's eligibility or a live result. Prices are USD where stated, excluding ad spend. Unless explicitly listed below, **Vietnam eligibility, Vietnamese support, minimum spend, and any missing paid-plan amounts are not stated on the cited official pages or are unverified**. An English documentation page proves documentation language, not the app UI, voice catalogue, or support service.

- **Read vs write:** [Marketing API authorization](https://developers.facebook.com/docs/marketing-api/get-started/authorization/) documents `ads_read` for reporting and `ads_management` for management. Standard Access can suffice for an own-account app where the caller has the appropriate app role and account access. For external advertisers, plan for Advanced Access on each needed permission, App Review and applicable Business Verification; see [Meta access levels](https://developers.facebook.com/docs/graph-api/overview/access-levels/). An approved permission alone does not grant access to the owner's assets. Review the current app type and endpoints before promising access. Vendor integrations do not transfer the vendor's approvals to this app; exact OAuth grants are unverified unless a cited vendor or Meta page specifies them.
- **Status push is a separate gate:** Meta's [Ads Webhooks setup](https://developers.facebook.com/documentation/ads-commerce/marketing-api/ads-webhooks/setup/get-started) requires `ads_management` to connect the app to the ad account and `ads_read` or `ads_management` to receive events. An alerts-only app can start by polling with read access and defer webhook onboarding rather than ask for write-capable access just to receive notifications.
- **CAPI sends store events; it does not read Ads Insights.** [Direct CAPI setup](https://developers.facebook.com/docs/marketing-api/conversions-api/get-started/) documents the Events Manager token path for an owner with the required business privileges, without separate App Review for that path; this is not an exemption for a third-party Marketing API app. Use [Meta's deduplication guidance](https://developers.facebook.com/docs/marketing-api/conversions-api/deduplicate-pixel-and-server-events/) when browser and server send the same Purchase. Do not send customer identifiers into a creative tool or alert channel.
- **Purchase math:** use [Ads Insights](https://developers.facebook.com/docs/marketing-api/insights/) at a consistent ad-account time zone, attribution window, currency and website Purchase definition. CPA = spend / attributed purchases; purchase ROAS = attributed purchase value / spend. Keep store orders and checkout events separate from Meta-attributed results. Mark no-purchase and low-volume windows distinctly; a 30-minute poll does not make purchase attribution real-time. Breakdowns and conversion counts do not establish that a particular hook caused a lift.

## Per-tool details

### Meta native

The built-in Ads Manager and Events Manager features below have **no separately listed feature subscription or trial** in the cited Meta docs; live ads still incur spend. Account-level eligibility, specific minimums, and rollout by country or creative language are not verified unless noted. Ads Manager features are Meta-only.

1. **Automated Rules — Meta (A).** [Evaluation filters](https://developers.facebook.com/documentation/ads-commerce/marketing-api/ad-rules/overview/evaluation-spec) and [trigger rules](https://developers.facebook.com/docs/marketing-api/ad-rules/guides/trigger-based-rules/) cover conditions such as cost per purchase, reach and supported spend/ROAS checks. [Schedules](https://developers.facebook.com/docs/marketing-api/ad-rules/guides/scheduled-based-rules/) include half-hourly, hourly and daily; supported change triggers can run on metadata or Insights updates, which Meta describes as seconds or minutes respectively, not a guaranteed alert or attribution SLA. [Execution options](https://developers.facebook.com/docs/marketing-api/ad-rules/overview/execution-spec/) include notification, stop/start and budget/bid changes; daily email summaries cover rule actions. Use Ads Manager without a custom app, or `ads_management` for API rule creation; build a read-only notification alternative with `ads_read`. **Use:** start with notify-only thresholds before enabling budget writes.
2. **Events Manager, Pixel and Conversions API — Meta (A).** [Verification guide](https://developers.facebook.com/docs/marketing-api/conversions-api/verifying-setup/) documents checking event receipt, delivery freshness, deduplication and match quality for events such as Purchase. Test Events and diagnostics are operator checks; an automatic alert cadence/channel or public API exposing the same diagnostics is **unverified**. No ad/budget actions. Needs access to the Pixel/dataset in Events Manager; CAPI requires a data-source token when sending server events, not for reading ad reports. **Use:** open this first when purchases drop in Meta but store orders do not.
3. **Advantage+ sales campaigns — Meta (S).** [Migration notice](https://developers.facebook.com/blog/post/2025/10/08/upcoming-asc-and-aac-mapi-deprecation-migration-options-to-advantage-plus/) documents the automation-first Sales setup and phased legacy Advantage+ Shopping Campaign (ASC) API deprecation; do not count legacy ASC as a second product or use its old creation API for new builds. Use Sales with website Purchase, the appropriate data source and assets. Setup in Ads Manager or write through Marketing API with `ads_management`; Pixel/CAPI supplies the outcome signal separately. **Use:** keep Meta's own delivery automation rather than trying to recreate it.
4. **Ads delivery status / Ads Webhooks — Meta (A).** [Effective status](https://developers.facebook.com/documentation/ads-commerce/marketing-api/ads-webhooks/effective-status) can push delivery changes, including disapproval; fetch documented review feedback for the reason. [Meta's webhook overview](https://developers.facebook.com/blog/post/2026/07/21/the-case-for-webhooks/) describes event-driven delivery, not a guaranteed delay; use [learning-stage info](https://developers.facebook.com/docs/marketing-api/reference/ad-campaign-learning-stage-info/) as a separate account/version-gated read to validate Learning Limited coverage. Reports issues, does not resolve them or automatically resubmit. Use Ads Manager manually or the Marketing API subscription/account grants above; no CAPI needed. **Copy:** event-driven alerts when eligible, polling fallback otherwise.
5. **Advantage+ creative — Meta (C, S).** [Creative API guide](https://developers.facebook.com/docs/marketing-api/creative/advantage-creative/get-started/) documents opt-ins for text/CTA enhancements, generated product backgrounds, image animation and other adaptations on eligible ads. Ads Manager previews are the place to check placement-specific rendering, asset eligibility and possible changes to claims; exact English/Vietnamese availability per enhancement is unverified. App-side launch needs `ads_management` and eligible creative assets; no CAPI for generation. **Use:** preview US English and packaging accuracy before applying enhancements.
6. **Advantage campaign budget (CBO) — Meta (A, S).** [Budget guide](https://developers.facebook.com/docs/marketing-api/bidding/guides/advantage-campaign-budget/) describes automatic distribution of campaign budget across ad sets. This is delivery optimisation, not a CPA/ROAS notification feature or guaranteed pacing; no alert cadence or channel. Configure campaign budget/eligible limits in Ads Manager or write with `ads_management`; use `ads_read` to report results. **Use:** let native delivery allocate, and show the owner why an app suggestion may conflict with that setup.
7. **Advantage+ audience — Meta (S).** [Audience guide](https://developers.facebook.com/docs/marketing-api/audiences/reference/targeting-expansion/advantage-audience/) documents expanding beyond audience suggestions while respecting controls such as location, minimum age, language and custom-audience exclusions. US is a targeting choice, not evidence of Vietnam account eligibility. Configure in Ads Manager or use supported ad-set fields with `ads_management`; no CAPI needed for the targeting setting. **Use:** let native delivery search; never have AI silently relax a hard location or exclusion.
8. **A/B testing / Split Testing — Meta (S).** [Split testing guide](https://developers.facebook.com/docs/marketing-api/guides/split-testing/) documents campaign/ad-set comparisons and creative tests through business ad studies; [eligibility tools](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-mcp-server/ads-mcp-server-tools-abtests-and-conversion-lift-studies) show that eligibility is checked per account/entity. Use native experiments; API creation requires a management flow with appropriate account/business access, and any additional endpoint grants are unverified. Test cost depends on the selected media budget; no universal minimum established. **Use:** predeclare the Purchase KPI, vary one concept and avoid declaring a winner from thin data.
9. **Meta AI — Meta (C).** The [Vietnamese public site](https://www.meta.ai/?locale=vi_VN) shows Vietnamese UI, caption drafting and image creation/editing. English and Vietnamese drafting are sensible manual workflows; ad-specific entitlements and Vietnam account-level rollout are unverified. The page does not state USD plan/credit limits for this use. Copy drafts manually into Ads Manager; no ad-account management integration or write scopes assumed for this workflow. **Use:** brainstorm English hooks, then review wording before use.

## Owner's choice: four feature packages

These are cumulative starting points, not commercial plans or a forced recommendation. Keep Meta account writes disabled unless explicitly approved. US copy is for customers; Vietnamese is the preferred language for owner-facing alerts and explanations.

| Package | What the owner gets | Build complexity |
|---|---|---|
| **A — Alerts only** | Find a spend, delivery or tracking problem early; no automatic edits. | **S** for one account with polling and a manual diagnostics fallback. |
| **B — Alerts + Optimisation** | Get daily recommendations; approve specific pause, scale or budget moves. | **M** for stateful rules, previews, guarded writes and audit history. |
| **C — Alerts + Optimisation + Creative AI** | Make and compare variants without adding automatic creative publication. | **L** for asset workflows, generation cost controls and measurement. |
| **D — Full Meta Ads copilot** | Go from product brief to reviewed campaign, controlled experiment and report. | **L** for entity creation, experiment eligibility and safe publishing. |

### A — Alerts only (MVP)

- **Features:** Poll for CPA and ROAS drift, CTR/CPM/CPC, conversion rate, frequency/fatigue and spend pacing at campaign/ad-set/ad level. Alert on disapproval, delivery blocks and Learning Limited where fields allow. Detect a Purchase/checkout event drop against store order totals and historical baseline, link to Events Manager for Pixel/CAPI verification, and distinguish “no events,” “stale pull,” and “not enough spend.” Offer hourly checks and a daily digest via email/in-app; add status push only if onboarding is approved. No pause, scale or publishes.
- **Reuse/replace:** Replace manual dashboard refresh with [Insights](https://developers.facebook.com/docs/marketing-api/insights/) and a Birch-style rule display; reuse native Ads Manager status, [Ads Webhooks](https://developers.facebook.com/documentation/ads-commerce/marketing-api/ads-webhooks/setup/get-started) optionally, and Events Manager for root-cause checks.
- **Data/access:** One authorized ad account, `ads_read`, time zone, USD spend/currency, attribution settings, aggregated store checkout/order/value counts (read-only store integration or CSV), and operator dataset access for the native diagnostics. No CAPI writer in this package. The webhook option needs `ads_management` for linking, even though the feature performs no ad changes.
- **Limits:** Small samples, attribution delay, stale/expired tokens and API rate limits all create false alerts. Use minimum spend/volume, consecutive windows, cooldown and account-time-zone comparisons; don't present a drop in attributed purchases as proof of broken tracking. No public parity with all Events Manager diagnostics established.

### B — Alerts + Optimisation

- **Features:** A plus daily account audit and ranked review queue: suggest budget reallocation, pause/scale, bid, audience or placement changes and creative refresh timing. Explain the data window, threshold and proposed before/after; run pause/scale rules in dry-run first, then require per-change approval before executing supported pause/scale and budget writes. Keep bids, targeting and placements suggestion-only initially.
- **Reuse/replace:** Borrow Birch's nested rules, Madgicx's audit and Creatify Max's approval card. Use Meta's [Automated Rules](https://developers.facebook.com/docs/marketing-api/ad-rules/) as a native comparison and [Advantage campaign budget](https://developers.facebook.com/docs/marketing-api/bidding/guides/advantage-campaign-budget/) as the allocator when enabled; don't issue contradictory ad-set changes.
- **Data/access:** A plus latest statuses, limits, budget ownership (campaign vs ad set), optional store margin/break-even CPA, `ads_management` and the owner's edit rights for write mode; `ads_read` alone for recommendation mode. No new CAPI dependency.
- **Limits:** A false positive can interrupt profitable delivery or send an ad set back into learning. Enforce owner-set spend ceilings, limited step sizes, cooldowns and fresh-data checks; re-read state before approved writes, deduplicate retries and log each action/result. API access or owner approval can be withdrawn.

### C — Alerts + Optimisation + Creative AI

- **Features:** B plus a Creative Studio: draft US English primary text, headlines, hooks and CTAs and Vietnamese review notes; generate approved packshot backgrounds and UGC-style scripts/storyboards or videos; export Feed 4:5, Reels/Stories 9:16 and a square variant when useful. Label concept, hook and asset IDs, preview crops/safe zones, and flag fatigue from rising frequency with declining CTR or worsening purchase efficiency. Compare variants using comparable windows and placement/attribution settings, not an AI score alone.
- **Reuse/replace:** Reuse approved Meta Advantage+ creative toggles in Ads Manager, optionally use Canva/Adobe for finishing and Creatify/Pippit for video, and copy Pencil's “insufficient data” treatment. Start with local export; vendor web products are not assumed to provide equivalent APIs or licenses.
- **Data/access:** B plus owner-approved product images, landing-page claims, brand guide, offer, asset rights and deployed ad-to-variant mapping. No Meta permission for generation or file export; `ads_read` for performance mapping, inherited write access only for B. No CAPI requirement beyond measurement signals already configured.
- **Limits:** Human review for likeness, commercial-use rights, synthetic testimonials, product/packaging fidelity, before/after imagery and unsupported hair or health claims under [Meta Advertising Standards](https://transparency.meta.com/en-us/policies/ad-standards/). Apply generation cost limits and send no shopper-level data to generation vendors. Fatigue signals are not causal tests.

### D — Full Meta Ads copilot

- **Features:** C plus a product URL/brief-to-campaign wizard: draft Sales objective, website Purchase, US audience controls, placements, test budget, ad sets and bulk ad variants. Show an itemized launch preview with destination URLs, expected budget/schedule, assets, placements and active enhancements. Create paused objects first; publish only after a separate owner approval. Run eligibility-checked creative A/B tests where supported and report spend, purchases, CPA/ROAS and sample sizes daily.
- **Reuse/replace:** Reuse current Advantage+ sales, audience, campaign budget and creative, plus native split testing; copy Canva Grow and AdEspresso's bulk workflow and Max's approval/audit design. Do not use a legacy ASC creation endpoint or emulate Andromeda. Fall back to a manual Ads Manager testing checklist if the account cannot create studies through the app.
- **Data/access:** C plus eligible ad account, Page and Instagram identity as applicable, selected website dataset, existing Pixel/CAPI Purchase signal, and catalog access only if a catalog is used. Use `ads_read` for reports and `ads_management` for campaign/ad-set/ad writes; validate applicable asset/task and business/experiment access with current Meta docs before implementation. Separate CAPI token/data-source access only if intentionally adding server-side event sending.
- **Limits:** App Review/Business Verification may be required for external accounts; identity, enhancements and experiments can be account-gated. Guard against duplicate or partly failed bulk operations, wrong account or objective and accidental budget activation. Check event setup, total budget, ad review status and enough Purchase data before interpreting a winner.

**Decision to make:** choose the bottleneck you want the app to solve first: missed problems (A), time spent choosing actions (B), time spent producing creative (C), or repeated campaign setup (D). A plus an export-only studio from C is a valid mix if creative speed matters more than budget automation.
